# Мониторинг забора

1. Загрузите index.html, build.py, README.md и папку data в корень публичного репозитория GitHub (ветка main). Добавьте также `.github/workflows/pages.yml` (в веб-интерфейсе можно создать файл с таким полным путём и вставить содержимое).
2. Settings → Pages → Source → GitHub Actions. В Actions выберите Publish fence monitoring → Run workflow → main. После успешного выполнения откройте ссылку в Settings → Pages.
3. Для следующей съёмки откройте data → Add file → Upload files. Имя файла: `cycle_01_2026-12-01.csv` (дата только пример, используйте фактическую). Commit changes в main. Следующие циклы: 02, 03 и т.д. Разрешены CSV и TXT. Строки без заголовка: имя,восток,север,высота,код. Все восемь точек X1–X8 обязательны, порядок строк произвольный. Десятичный разделитель — точка.
4. Actions покажет результат проверки и публикации. При ошибке исправьте файл; предыдущий опубликованный сайт сохранится. Ссылка у заказчика не меняется.

Дата нулевого цикла неизвестна. При необходимости переименуйте cycle_00.csv в cycle_00_ГГГГ-ММ-ДД.csv с фактической датой.

Публичный репозиторий и сайт раскрывают исходные координаты. Публикуйте только с разрешения владельца данных. Допуски и точность определяются программой наблюдений.

Локальная проверка: python build.py, затем откройте _site/index.html. Не добавляйте _site в репозиторий.
